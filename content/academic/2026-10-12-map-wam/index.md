## 1. 为什么值得读

机器人失败未必意味着不会抓取或移动，也可能是忘记历史、判断错任务阶段。教师接管时，除了纠正动作，还可以提供“接下来做什么、预期看到什么、什么时候算完成”的恢复计划。

MaP-WAM 验证了记忆与进度机制在特定任务中的价值，为失败诊断与教师接管提供了一个切入点。不过，它尚未验证教师恢复示范能否让学生学会独立修复，也没有回答最少需要补充多少新经验。

**一句话总结**：先用长期真实历史生成下一段语言与视觉计划，再让执行器结合当前状态预测动作和进度，通过观察校正进度并决定何时切换子任务。

## 3. 问题背景：当前画面为什么不够

许多机器人策略主要根据当前画面或短历史决定动作，但当前画面未必包含决策所需的全部信息。

例如，机器人先看到三个不同颜色的按钮，随后按钮被盖住，再收到“打开红色按钮的盖子”的指令。此时，抓取技能再好，也必须记住红色按钮原来的位置。

另一个问题是，相似画面可能对应不同阶段。机械臂在按钮上方，可能是准备按下，也可能是已经按完、准备离开。只看当前图像容易重复按压或漏按。

现有路线存在取舍：把历史压缩成语言摘要可能丢失精细空间证据；把越来越长的图像历史反复输入动作模型，则会增加推理和显存成本。

作者提出：长期历史主要用于确定下一段计划，执行器反复生成动作时只读取当前状态和这段计划。这样，长期记忆可以继续积累，执行器输入长度仍保持固定。固定的是执行器上下文，不代表整个系统的记忆存储或规划成本严格不变。

## 4. 核心方法：记忆、计划、动作与进度

### 4.1 三个组件分别负责什么

| 组件 | 基础模型与作用 |
| --- | --- |
| 语言规划器 | 微调 Qwen3.5-4B，根据全局任务、历史子任务和关键帧决定下一段做什么 |
| 视觉规划器 CWM | 基于 WAN-2.2-5B 的因果世界模型，结合历史生成下一段预期的视觉过程 |
| WAP 执行器 | 视频、动作、进度专家组成的模型，根据计划与当前状态预测动作块和对应进度 |

语言规划器使用 LoRA 微调；视觉规划器和 WAP 也需要训练。它不是可以直接附加到原生 π0.5 上的免训练插件。WAP 的动作专家约 1.02B 参数，进度专家约 207M 参数。

### 4.2 将真实执行历史保存为分段记忆

每完成一个子任务，系统存下该段语言描述和均匀抽取的 **8 帧真实图像**，并单独保留整个任务的初始观察。

语言规划器读取初始帧及各已完成段的末帧；视觉规划器读取更完整的稀疏视觉历史。前者负责下一段语义目标，后者保留物体位置等视觉证据。

### 4.3 生成语言与视觉计划

语言规划器先预测下一段目标，视觉规划器再根据这个目标和历史证据生成预期画面序列。视觉计划提供空间和动态参考，补充语言描述难以表达的细节。

视觉规划器采用分段因果注意力：历史段不能看到未来段，已完成段的表示可以缓存。WAP 也把当前视觉计划作为静态前缀，在该段执行期间复用缓存。

### 4.4 联合预测动作与进度

WAP 根据视觉计划、子任务指令、当前观察、本体状态和当前进度，预测动作块以及对应的未来进度。训练时还包含未来视觉预测作为辅助目标；结构化注意力将其与动作、进度分支隔离，因此部署时可省略执行器的未来视觉预测分支。独立的视觉规划器仍需生成视觉计划。

训练进度标签由示范片段的时间位置构造：

$$
p_t = \frac{t-i}{j-i}
$$

其中，$i$ 和 $j$ 是该段示范的起止时刻，开始为 0，结束为 1。

**这个标签表示示范中的归一化时间位置，不能直接理解为任务成功概率或物理目标完成百分比。**

训练采用视觉、动作和进度三个分支的条件流匹配损失，权重均为 1。模型训练时预测 32 步动作；推理时执行前 8 步，再更新观察与进度。动作与进度生成使用 10 步去噪。

### 4.5 用观察校正进度，再切换子任务

推理时没有真实进度标签，模型只能递归使用自己的预测，因此误差可能积累。

作者把段初始观察和 8 帧生成计划组成 9 帧参考序列，并赋予从 0 到 1 的进度坐标。每次预测动作前，从当前估计进度附近选出两帧参考图，使用 RGB 平均绝对像素差寻找更接近当前观察的参考帧，再将当前进度与该参考帧进度取平均。

最近执行动作对应的平均预测进度超过 **0.95** 时，系统结束该段、更新记忆，并规划下一段。写入记忆的是 **真实执行画面**，不是生成的理想画面。

整体流程为：

```text
真实历史与全局指令
    → 下一段语言目标与视觉计划
    → 当前观察与进度校正
    → 动作块与进度预测
    → 执行动作并获取新观察
    → 未完成则继续；完成则记录真实历史并规划下一段
```

## 5. 实验设计与主要结果

### 5.1 仿真：记忆依赖任务

仿真实验采用 RMBench 的 9 个任务，涵盖依赖单个或多个关键历史观察的决策。每个任务使用 **50 条专家示范、100 次评估 rollout**。规划器采用多任务训练，WAP 执行器按单任务训练；评估使用全局种子 0。

| 方法 | 9 个任务平均成功率 |
| --- | ---: |
| Diffusion Policy | 5.8% |
| π0.5 | 10.4% |
| Mem-0 | 42.0% |
| LingBot-VA | 77.1% |
| MaP-WAM | **83.3%** |

这些数字限定于该基准与训练配置，不能推出 MaP-WAM 在一般桌面操作上全面优于 π0.5。

它也不是每个任务都领先：Rearrange Blocks 上 MaP-WAM 为 **66%**，LingBot-VA 为 **100%**；Observe and Pick Up 上，MaP-WAM 虽然达到 **19%**，高于表中其他基线最高的 9%，但绝大多数试验仍失败。论文将后者的困难与物体类别较多、跨时间视觉推理及有限示范联系起来。

### 5.2 真实机器人：两项记忆任务

真实实验使用 **Franka Research 3**，配备第三视角与腕部 RealSense D435i 相机。每项任务采集 50 条训练轨迹，再测试 50 次。

| 任务 | 内容 | 成功率 |
| --- | --- | ---: |
| Find Button | 先观察按钮颜色，遮挡后根据白板指令找出目标 | 88% |
| Press Buttons | 记住白板上的两个数字，按指定次数操作左侧和中间按钮，最后按右侧确认按钮 | 68% |
| 两项平均 | — | **78%** |

Press Buttons 的具体设置是按白板数字分别操作左侧和中间按钮，最后按右侧确认按钮。真实实验覆盖两项记忆任务，尚不足以证明广泛的恢复能力。

### 5.3 进度消融：为什么“知道做到哪一步”有帮助

在 Blocks Ranking Try、Cover Blocks 和 Press Button 三个选定仿真任务上，作者比较不同进度机制：

| 配置 | 三项平均成功率 |
| --- | ---: |
| 用完成/未完成分类替代进度机制 | 37.0% |
| 预测进度，但不将当前进度输入执行器 | 54.0% |
| 不做视觉进度校正 | 73.7% |
| 完整方法 | **96.7%** |

该结果支持：在这些阶段容易混淆、历史依赖较强的任务中，让执行器知道当前阶段并校正阶段估计，有助于可靠执行。按按钮任务尤其容易混淆按下与释放阶段；较长的方块排序任务则更容易积累进度误差。

消融同时改变相关结构与训练方式，不能把全部收益归结为“多加一个进度数字”。视觉校正也并非每项都提高成功率：Press Button 上，不做校正为 98%，完整方法为 96%。

### 5.4 效率：固定执行上下文的价值与边界

执行器每个动作块的推理延时约 **827 ms**，随历史增长大致保持稳定。对照的全历史执行器即使使用 KV 缓存，在 1,500 帧历史时延时也约为零历史时的 4 倍；1,700 帧时显存超过 80 GB。

测量使用单张 A800-SXM4 80GB、BF16、批量大小 1、10 步去噪。**这些数字排除了模型加载、提示编码、数据传输、VAE 编解码和缓存预填充开销，不能作为完整控制延时。**

## 6. 可以借鉴什么，不能据此声称什么

被实验支持的思路是：保留真实历史证据，在子任务边界生成紧凑计划，再用进度感知的执行器完成计划。它把长期记忆处理与频繁动作生成分开，同时通过真实观察更新记忆。

成立条件包括：能够构造有意义的子任务分段；任务确实依赖历史或阶段；视觉计划足以提供参考；训练数据能覆盖相关执行过程。

主要局限如下：

- 依赖已有示范分段和子任务标注，尚未解决自动发现任务边界。
- 进度来自示范时间位置，恢复、反复尝试或绕路时，语义进度未必单调。
- RGB 匹配容易受视角、光照、遮挡和生成画面误差影响。
- WAP 训练使用真实示范计划，推理使用生成计划，存在输入分布差异。
- 训练使用 8 张 A800，尚未证明低成本适配现有 π0.5 的可行性。
- 没有验证失败原因诊断、教师接管、最少补采数据或学生减少教师依赖。

## 7. 对 VLA 自主诊断与教师恢复学习的启发

我们关心的研究问题是：**强 VLM 能否在 VLA 的失败状态下生成有效恢复示范，并通过少量训练，让 VLA 在未见同类场景中减少对老师的依赖？**

MaP-WAM 为其中的历史记录、阶段判断和恢复完成检测提供了参考。它提醒我们，应区分动作技能不足、历史信息缺失和阶段判断错误。不同原因可能需要不同的恢复数据或模型接口。

我们此前观察到，多物体场景与两步指令高度相关时，模型会在单步指令下多做动作；补充少量“多物体、单步操作”示范后问题得到改善。这更直接指向视觉捷径与数据相关性，不能假设加入记忆就能解决，但可以检查是否同时存在阶段或完成条件判断错误。

以下为研究设想，尚未由该论文验证，也不意味着已经确认是全新方向。

### 设想一：教师先输出恢复子目标、阶段与完成条件

- **核心假设**：部分失败可通过明确恢复计划解决，不必让教师直接控制每一步动作。
- **最小实验**：构造抓空、放偏、重复操作三类失败状态，比较原生 π0.5 重试、VLM 仅给恢复指令、VLM 给恢复指令加阶段与完成条件。
- **指标**：恢复成功率、重复动作率、教师调用次数和总耗时。
- **主要风险**：现有 π0.5 未受过对应条件训练，可能无法利用阶段或视觉计划；应先用它可接受的语言接口验证，再考虑额外条件分支。

### 设想二：恢复数据同时监督动作和任务阶段

- **核心假设**：在同样数量的恢复示范下，显式阶段监督能减少学生在相似失败中的混淆。
- **最小实验**：固定教师恢复数据预算，比较普通行为克隆与加入阶段监督的学生。留出部分物体、位置与失败严重程度用于未见测试，并控制训练预算。
- **指标**：关闭教师后的独立恢复成功率，以及固定检测器下的教师接管率；同时报告采集与训练成本。
- **主要风险**：直接按时间生成标签可能把失败动作也标成进步，需要检查标签与实际任务状态是否一致；还要评估原有正常任务是否退化。

这些实验需要分别证明“系统借助老师能够恢复”和“学生经过学习能够独立恢复”。MaP-WAM 本身只为相关记忆与进度机制提供证据，尚不能替代后一个验证。
