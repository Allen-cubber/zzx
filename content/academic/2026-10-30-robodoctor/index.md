## 1. 为什么今天值得读

机器人已经学会抓取和放置，却仍可能在目标选择、局部对齐或接触方式上失败。遇到这些错误，是否必须立即采集新数据、微调整个策略？RoboDoctor 提供了一条可以先验证的路线：保持模型权重不变，改变谁控制、何时纠正，以及如何保存和使用执行经验。

这篇论文与“强 VLM 为 VLA 做老师，在失败时生成恢复示范”的方向直接相关。相比此前 InternW0-Δ 中简短的 Astra 纠正实验，RoboDoctor 更具体地描述了建议动作与实际执行如何分离、局部纠正如何限制步数、结果如何记录。它适合作为接管系统的机制参考。

不过，它没有验证把恢复示范训练回学生后的独立能力。更重要的是，主实验来自经过回顾性筛选的运行记录，并非预算严格匹配的记忆消融。本文选择它，是因为控制接口和证据记录方式有可借鉴价值；不是因为它已经证明了通用、稳定的递归自我改进。

## 3. 核心变化：把执行过程作为改进对象

传统的数据闭环通常是：发现错误，采集纠正数据，再更新策略参数。RoboDoctor 则固定机器人策略和 Doctor 代理的权重，让新的经验改变后续的控制决定。

其适应状态包含选定的控制模式、任务相关的外部经验，以及经验指导下的介入与物理操作方法。论文中的 RSI 是这种外部状态更新与复用，不代表机器人持续修改自身神经网络，也不代表任意代码都能自动进化。

| 改进层次 | 要回答的问题 | 例子 |
| --- | --- | --- |
| Harness RSI | 主要由策略执行，还是由 Doctor 直接组织执行？ | 底层策略一直用错工具操作方式时，改由代理规划 |
| Intervention RSI | 哪部分策略行为可以保留，什么时候需要纠正？ | 已经抓稳瓶子，只纠正瓶口相对杯口的偏移 |
| Operation RSI | 纠正应采用什么具体接触方式，怎样验证？ | 调整夹爪闭合方向，先小幅抬起检查是否抓稳 |

这三个层次的区分很有用：一个失败可能来自任务策略错误，也可能只是几何对齐误差；如果每次都重新抓取或全面接管，就可能破坏策略本来已经做对的部分。

## 4. 模型与传感器：Doctor 到底能看到什么

论文评测使用冻结的 PrismWAM 作为机器人策略。它根据指令和观测历史生成动作块：

$$
A_t=\pi_\theta(h_t,\ell)\in\mathbb R^{32\times14}.
$$

每个时间步的 14 维动作对应双臂：每只手臂六个绝对关节目标，加一个夹爪开度。

Doctor 是冻结的多模态代理，可读取头部和腕部 RGB、度量深度、测量关节状态及末端位姿；正文说明它不使用特权物体位姿或物体状态标签。环境原生评分用于回合结果和模式选择，与逐步控制时直接获取物体真值是不同的接口。

不能把全文结果一概写成“某个固定 Astra 配置加 PrismWAM 的提升”。第 4.1 节明确指出，归档包含多个来源运行，尚未建立统一的代理版本、检查点和推理预算。GPT-6-Astra 在主结果中也是公开榜单参考项。当前代码支持可配置模型，不能据此确定全部历史运行的老师版本。

## 5. Harness：先决定谁负责主要控制

每次运行先做三个 Hybrid 热身回合，对应迭代 0、1、2，期间已允许 Doctor 协助并传递经验。

设三个有效回合的原生平均分为 $\bar s_W\in[0,1]$，后续使用：

$$
c=\begin{cases}
\mathrm{Direct},&\bar s_W<0.30,\\
\mathrm{Hybrid},&\bar s_W\geq0.30.
\end{cases}
$$

Hybrid 由策略提出主要运动，Doctor 审查并局部修正；Direct 则由 Doctor 通过具备几何定位的控制工具直接规划和发出运动。所选模式在该运行的后续回合保持固定，不是每一步重新进行任意模式切换。

继续 Hybrid 时沿用介入经验；切换 Direct 时初始化另一份任务经验文档，后续 Direct 回合继承它。不能假设 Hybrid 的全部经验自动无损转入 Direct。

这个 0.30 门槛是粗粒度控制权分配规则，不是一个学出来的细致根因诊断器。低分只能说明当前组合效果差，不能单独判断问题来自识别、接触、规划还是低层能力不足。

## 6. Intervention：让策略先提案，再决定是否执行

这是最值得在自己的实验中复用的接口。

### 6.1 提案阶段不动机器人

策略先返回 32 步动作，以及只涉及机器人自身的正运动学预览。Doctor 将候选运动与当前 RGB-D、机器人实测状态、已有经验对照。

正运动学预览可以帮助判断机械臂大致会到哪里，但不能预测物体接触、滑动或抓取结果。它不是环境物理仿真，也不是成功证明。

### 6.2 每次只选择一种执行分支

| 分支 | 执行内容 | 限制 |
| --- | --- | --- |
| 放行策略 | 原样执行当前动作块的前缀 | 一次 1—16 步，不改写前缀 |
| Doctor 纠正 | 用工具替换当前执行动作 | Hybrid 中每次 1—5 个物理步 |

两条分支执行后都获取新观测，丢弃未使用的旧动作后缀，再生成下一份策略提案。一次纠正不足，可以继续纠正，但每次都要经过新观测和新提案。

这里的“步”是物理控制步数，不是语言模型推理 token 数。五步上限限制单次开环动作长度，不构成碰撞避免或形式化安全保证。

所有实际执行过的帧——包括 Doctor 的纠正——都会进入策略的观测历史。否则，策略下一次推理仍可能基于不完整的执行历史，和老师刚做完的纠正产生冲突。

### 6.3 先保留正确行为，再修正局部问题

倒水案例中，策略已经抓住瓶子，但瓶口横向偏离杯口。Doctor 做一次横向纠正，保持夹持不变，然后让策略继续倾倒。这里要修的是对齐，而非重新学习抓取或把整个任务交给老师。

这提示我们，接管系统的目标不应只有“发现不对就介入”，还应该识别并保留当前已经有效的行为。是否真的减少老师调用和成本，仍需单独实验，本文没有提供完整成本统计。

## 7. Operation：诊断必须落实到接触方法和结果验证

识别“抓取失败”并不足以产生有效纠正。Doctor 通过像素与深度定位可见表面，再结合末端实测位姿，构造接近方向、接触区域、手腕朝向、夹爪时机、运动顺序和另一只手臂的角色。

一个深度点只说明某个可见表面的位置，不自动等于可用的夹爪接触点或末端目标。

作者区分了两类反馈：

- 指令目标没有到达，应先检查运动与构型。
- 已到达目标，但物体滑落，应重新检查接触和夹持方法。

搭塔案例中，Doctor 将容易滑动的抓取改成端面抓取，并先做短距离试抬。确认物体仍被夹持后才运输和放置。

这里可借鉴的是“用一个短操作检验局部假设”：试抬可以检查抓稳没有，局部横移可以检查是否对齐。但试抬成功不等于整个放置任务已完成；倒水姿态对齐也不等于液体已进入杯中。

附录 A 还说明，接触区域、试抬、双臂分工和视角变化等指导在交互前已经提供。因此，不能把每个案例都解释成模型从零自主发明了接触知识。

## 8. 经验记忆：保存证据，而不是只写一句“下次小心”

Hybrid 经验记录把诊断与操作关联起来，保存触发证据、策略状态、尝试方法、结果和适用条件；既保留失败，也记录自主成功与介入事件。

例如，可以将倒水案例抽象为以下结构。此表是本文对字段的解释性示例，不是作者逐字日志：

| 字段 | 示例内容 |
| --- | --- |
| 触发证据 | 当前视角显示瓶口与杯口横向不对齐 |
| 保留的行为 | 当前抓持稳定，暂不松开夹爪 |
| 尝试的方法 | 根据新深度信息计算横向修正 |
| 局部结果 | 新图像显示瓶口对齐改善 |
| 尚需验证 | 继续倾倒后是否发生液体转移 |
| 复用条件 | 当前仍稳定夹持、能够观察杯口与瓶口 |

复用的是“先对齐并保留稳定抓持”的方法，而不是旧场景的一组绝对坐标。每次都要根据新画面重新计算动作目标。

记录可以新增，也可以按标识修订；宿主程序检查必填字段、版本并保存快照。这个检查只保证文档结构有效，不能证明诊断是真的，也不能自动消除语义矛盾。

Direct 模式使用任务计划和详细笔记，回合结束后在禁止动作工具的总结阶段归纳经验。宿主附加原生评分、有效性和成功标志，下一回合重新确认场景与进度。旧回合“已完成”的步骤不能直接当成新回合的事实。

### 四种证据不能混为一谈

| 证据 | 能支持什么 | 不能单独证明什么 |
| --- | --- | --- |
| 候选动作和 FK 预览 | 机器人打算怎样运动 | 实际物体运动和接触结果 |
| 实测末端位姿 | 机器人实际到了哪里 | 抓稳、放准或任务完成 |
| 新的 RGB-D | 可见的接触、支撑、转移和失败 | 隐藏的定量成功条件 |
| 环境原生结果 | 评测器定义的分数与完成情况 | 某次介入或某条记忆带来的因果收益 |

这张证据表比笼统的“让 VLM 反思”更具体，也适合用于人采恢复示范的数据标注。

## 9. 实验设计与结果：先看协议，再看分数

### 9.1 这是 54 个任务条目的归档分析

评测位于 RoboDojo-Sim，包含 24 个泛化条目——12 个标准与 12 个随机化条目——以及精度 8、长程 8、记忆 6、开放指令 8 个条目。不能把所有条目都理解成不同语义任务。

热身为迭代 0—2，改进阶段为迭代 3—8。**热身已经有老师和记忆，不是裸策略，也不是无记忆基线。**

归档合并多个来源运行；同一候选位置按最高有效分等规则筛选结果，来源模型、预算和记忆历史并未完全统一。有效记录要求完整、标记可评测、分数有限且位于合法范围；零分的有效记录仍保留，缺失或无效记录不作为零分参与。

因此，阶段差异同时混合更多交互、经验更新、路由改变和记录选择，不能把差值直接归因于跨回合记忆。

### 9.2 总体结果

| 方法／阶段 | Score | 原生成功率 | 有效／计划回合数 |
| --- | ---: | ---: | ---: |
| RoboDoctor Warmup | 49.74 | 40.83% | 162/162 |
| RoboDoctor Refinement | 57.10 | 49.44% | 301/324 |
| HexaShell-Preview，公开参考 | 53.18 | 46.85% | 未在此表统一 |
| VPP2，公开参考 | 39.26 | 32.26% | 未在此表统一 |
| GPT-6-Astra，公开参考 | 28.97 | 22.48% | 未在此表统一 |

来源：论文表 1，公开参考采用 2026 年 10 月 20 日归档榜单。先对每项任务平均，再按能力维度平均，最后五个维度等权汇总。因此 49.44% 不是简单用全部成功次数除以 301。

Score 允许部分进展得分；成功率来自原生布尔成功标志。57.10 是分数，不能写成 57.10% 全任务成功率。

两阶段报告的成功率增加 8.61 个百分点。但与公开参考之间没有统一的交互预算、运行筛选和模型配置，表中更高的归档成绩不能当成严格同条件排名或某个模块的独立收益。

### 9.3 改善并不一致

| 能力维度 | Warmup Score | Refinement Score |
| --- | ---: | ---: |
| 泛化 | 47.50 | 56.98 |
| 精度 | 43.54 | 47.60 |
| 长程 | 54.58 | 52.92 |
| 记忆 | 73.89 | 77.50 |
| 开放指令 | 29.17 | 50.52 |

来源：表 2。54 个任务条目中，24 个改善、20 个下降、10 个不变。整体分数提高与不少任务退化同时存在，长程维度也下降。

附录 B 的 build_tower 改进阶段成功率为 100%，但有效回合只有 3/6，不能写成六次都成功。倒水案例虽展示一次有帮助的局部纠正，该任务两阶段平均 Score 都是 66.67；一个好的片段不等于任务总体成绩上涨。

基准中的 Memory 维度测的是指定的记忆任务表现，不是对本系统外部经验机制的消融，不能用该列上升单独证明记忆模块有效。

## 10. 已有证据、限制与复现注意点

作者已提供的主要证据，是一套可描述的执行机制、具体操作变化记录，以及所选归档运行的总体结果。策略切换、保持抓持的局部纠正、试抬后再运输等案例说明这些行为确实出现在记录中。

尚未证明的包括：持久记忆比每回合清空记忆更好；三回合门槛优于固定控制模式；同等成本下优于其他系统；能迁移到不同策略或真实机器人；能减少老师依赖；以及少量轨迹微调后学生可独立恢复。正文第 6 节也明确提出这些证据边界。

“Training-free”只表示不更新模型权重。多模态代理推理、策略调用、几何查询、环境交互和记录处理仍要花时间。短动作片段提高反馈频率，也可能显著增加延迟；论文没有汇总完整成本分析。

代码可以公开访问，是机制复现的有用起点，但当前 README 与 v1 并非严格同一快照：

- 当前 README 描述了继续 RSI 分支前的一次提示指导修订，以及固定后续提示快照。v1 对受评估 harness 的表述主要是预定义控制器之间的选择，不能将全部归档改善归因于自动提示改写。
- v1 附录提到一个预览后端使用四个历史 RGB 加当前帧；当前 README 的默认 PrismWAM 后端说明是开局、32 步前、当前三份 RGB。复现应固定实际配置，不能混写两种历史采样方式。
- 当前代码提供 π0.5 接口，不等于本文已完成 π0.5 上同等实验；正文报告的底层策略为 PrismWAM。
- 项目页部分说明仍提到十项局部任务，而论文和当前 README 给出 54 项归档。本文数字统一以所读 v1 的表格为准。

这些差异不意味着某个实现不能使用，但意味着必须记录代码版本、模型版本、传感器历史、路由、提示和交互预算，才能解释一次复现实验。

## 11. 对具身智能与我们实验的具体启发

第一，诊断最好直接服务于一个可验证操作。例如“夹爪没有到位”应对应位置误差检查，“已到位但抓不稳”应对应接触方法检查。抽象失败标签本身不提供恢复能力。

第二，将动作提案和实际执行分开。这样老师能够在动作执行前审查，且能把“允许通过”和“主动纠正”分别记录。这比事后只保存成败更容易分析老师为何介入。

第三，成功行为也值得保存。针对我们多物体桌面上的语言捷径，应记录“只操作目标物体并停止”的成功证据，而不仅积累错误日志。否则经验文档可能只包含如何继续行动，却不包含何时应该停止。

第四，区分系统进步与学生进步。RoboDoctor 的在线系统可通过外部状态改变行为；若我们的目标是老师最终少介入，还必须把成功纠正转成动作示范，并做老师关闭后的评测。本文的经验文档不是已经验证可直接用于策略微调的数据集。

第五，最小新增经验应按完整获取成本衡量。保留五条恢复示范可能花了大量尝试。应同时记录成功片段、失败尝试、老师控制时长和更新算力，不能只报告最后进入训练集的条数。

## 12. 两个可验证的研究设想

以下是由本文启发的研究设想，不是作者已验证的结论，也不主张已确认是全新方向。

### 设想一：外部经验究竟能否改善下一回合

**核心假设：** 在固定老师、学生和控制模式时，带适用条件与结果证据的经验，比不继承经验更能提高新布局下的恢复效率。

**最小实验：** 选择目标选错、抓取偏位、阶段切换三类桌面失败；先固定 Hybrid，排除路由变化。在相同布局种子、调用预算和机器人执行步数下，比较每回合清空经验、保留普通文字总结、保留结构化诊断—操作—结果记录三组。每种失败可先用约 20 个预先固定的测试布局估计趋势，记录不确定性，样本不足时不声称稳定优势。

**指标：** 全任务成功率、每次成功所需老师调用数、老师控制步数、错误介入比例和总墙钟时间。外部经验在新的测试布局前冻结，避免把测试集学习混进迁移成绩。

**主要风险：** 记忆更长会增加推理预算；错误经验可能持续传播。应控制上下文长度或单列 token 成本，并审查失败经验是否被错误总结成通用规则。

### 设想二：把局部纠正转成少量恢复示范，逐步减少老师依赖

**核心假设：** 相同获取与训练预算下，从学生自然失败状态生成的局部成功恢复片段，比从正常初态补采完整示范更能改善未见同类失败上的学生独立表现。

**最小实验：** 先用冻结老师收集恢复片段，同步保存干预前后图像、机器人状态、实际执行动作、介入边界与结果。比较不更新、普通成功示范补采、局部恢复示范补采三组；按 5／10／20 条形成预算曲线，并按动作帧数和交互时长补充公平比较。保持学生初始化、训练步数和原数据回放比例一致。

先在关闭老师的未见位置、干扰物和物体组合中评测，再使用相同介入规则测老师依赖。可以积累一批片段再更新，无需每次接管后立即微调。

**指标：** 学生独立成功率与恢复率、原技能退化、老师调用次数及控制时长、有效片段获取率、训练耗时。老师调用下降必须以不牺牲任务成功率为前提。

**主要风险：** 老师轨迹可能突兀、难以模仿；只选成功片段会掩盖获取成本；局部修正可能与学生后续动作不兼容。应保留完整尝试日志，检查接管与交还控制的衔接，并将老师的语义判断与实际执行动作标签分开存储。
